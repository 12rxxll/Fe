# FE Learning OS v2

基本情報技術者試験の用語学習・問題演習・復習管理を行う、無料のブラウザアプリです。

## 収録内容

- FE用語 955語
- FEシラバス Ver.9.2 の用語例を補助収録（追加データ 3,012件、用語結合後 3,958語）
- 知識マップ初期データの不足語を補完（33語、学習対象合計 3,991語）
- 知識マップは学習対象3,991語を全件表示（122カテゴリ、関連・前提関係 15,656本）
- 知識マップ内の用語検索・分類・状態・記述フィルター
- 自分の言葉で説明する記述欄と自動保存
- 記述進捗とテスト進捗の分離表示
- 理解度 Lv.0〜5
- 4択問題（説明→用語／用語→説明）
- 問題演習の途中保存・再開
- ランダム・苦手優先・未学習優先・復習期限モード
- 間隔反復による復習期限管理
- 誤答ランキング・分野別正答率・14日間活動グラフ
- ブックマーク・自分用メモ
- 記述内容をまとめてChatGPTへ送るプロンプト生成
- 用語ごとの説明をChatGPTへ質問する補助プロンプト生成
- 関連用語のカード内展開と知識マップ内ジャンプ
- JSONバックアップ／復元
- ダークモード
- PWA・オフライン対応
- GitHub Pagesで無料公開可能

## すぐ試す

`index.html` を開くと基本機能を確認できます。ローカルファイルではPWAインストールとService Workerは動作しませんが、学習・問題・進捗保存は動作します。

## GitHub Pagesで無料公開

1. GitHubで新規リポジトリを作成します。例：`fe-learning-os`
2. このフォルダ内のファイルをすべてリポジトリ直下へアップロードします。
3. GitHubの `Settings` → `Pages` を開きます。
4. `Build and deployment` の Source を `Deploy from a branch` にします。
5. Branch を `main`、フォルダを `/(root)` にして保存します。
6. 数分後に表示されるURLへSafariでアクセスします。
7. iPhoneでは共有ボタン →「ホーム画面に追加」でアプリ化できます。

## データ保存について

学習データはブラウザの `localStorage` に保存されます。別端末との自動同期はありません。設定画面から定期的にバックアップしてください。

### 現在の保存形式

- 保存キー: `fe-learning-os-v2`
- 形式バージョン: `version: 2`
- データスキーマ: `schemaVersion: 14`
- `settings`: `dailyGoal`, `examDate`, `theme`
- `terms`: 用語IDごとの理解度、正答数、誤答数、知識マップ連動の重み付き正誤、連続正解、連続不正解、復習間隔、復習期限、次回復習日、最終学習日、最終正解日、最終誤答日、優先度、苦手理由、ブックマーク、メモ
- `knowledgeNotes`: 旧知識マップメモ互換用。削除せず残します
- `termNotes`: 知識マップ用語IDごとの記述内容、更新日時、記述状態、ChatGPT確認状態、最終送信内容、最終送信ハッシュ、最終送信日時、送信バッチID、修正メモ、修正メモ反映日時、反映方式、反映後内容
- `noteRevisionHistory`: ChatGPT修正メモを記述へ反映したときの直近履歴。用語IDごとに反映前内容、反映後内容、変更日時、反映方式を最大10件保存
- `memorizationRatings`: 暗記モード専用の自己評価。最終評価、評価日時、覚えていた/あいまい/覚えていなかった回数を保存
- `quizDraft`: 中断中の問題演習。セッションID、開始/更新時刻、出題モード、分野、問題数、形式、出題済み問題、現在位置、回答済み結果を保存
- `uiState`: 問題設定画面の選択値、マップのスクロール位置、開いていた用語、関連用語アコーディオンの展開状態を保存。用語詳細カードの説明/復習/詳細進捗アコーディオンは再読み込み後は閉じた状態で開始します
- `chatgptSubmissionBatches`: ChatGPTへ送るために作成・コピーした記述プロンプトの履歴。対象用語、範囲、文字数、プロンプトハッシュ、状態を保存
- `attempts`: 解答履歴。用語ID、正誤、日付、時刻、出題モード、問題形式、分野を保存
- `sessions`: 演習セッション履歴。日付、モード、問題数、正解数、所要時間を保存
- `subjectA`: 科目A対策問題の問題別正誤、解答履歴、セッション履歴を保存

既存データとの互換性を保つため、保存キーと `version: 2` は変更しません。旧データは読み込み時に不足フィールドを補完して `schemaVersion: 14` へ移行します。既存の `terms[*].note` や `knowledgeNotes` は削除せず、新しい `termNotes` からも互換的に読めるようにしています。破損したJSONや異なるバージョンは読み込まず、既定値で起動します。

## 現在の実装仕様

### ファイル構成

- `index.html`: 画面のHTML、PWA manifest、アイコン、CSS、JSの読み込み
- `assets/styles.css`: 画面レイアウト、スマホ表示、ダークモード
- `assets/app.js`: 状態管理、画面遷移、検索、問題演習、復習、分析、設定、バックアップ
- `assets/terms-data.js`: `window.FE_TERMS` として読み込むFE用語データ
- `assets/syllabus-terms.js`: `window.FE_SYLLABUS_TERMS` として読み込むFEシラバス用語例の補助データ
- `assets/subject-a-data.js`: `window.FE_SUBJECT_A_QUESTIONS` として読み込む科目A対策のオリジナルサンプル問題
- `assets/knowledge-map-data.js`: `window.FE_KNOWLEDGE_MAP` として読み込む知識マップ用の分野、カテゴリ、用語、関係、問題関連付けデータ
- `assets/knowledge-map.js`: 知識マップの全用語取り込み、グラフ構築、状態判定、前提循環検出、カテゴリ進度、次に学ぶ推薦のサービス層
- `manifest.webmanifest`: PWA名、起動URL、scope、アイコン、ショートカット
- `sw.js`: オフライン用キャッシュとナビゲーション時のフォールバック
- `icons/`: 192px、512px、maskable 512px のPWAアイコン
- `.nojekyll`: GitHub Pagesで静的ファイルをそのまま配信するためのファイル

### 用語データ

`assets/terms-data.js` には955語を収録しています。`assets/syllabus-terms.js` には、FEシラバス Ver.9.2 の用語例から、既存データで扱えるものを除いた3,012件を補助収録しています。アプリ起動時に両方を結合し、同名語の重複を除いた3,958語を検索、理解度管理、4択問題、復習、分析の対象にします。さらに `assets/knowledge-map-data.js` の初期マップ用語のうち既存データに同名語がない33語を、通常の用語カード形式へ補完して学習対象にします。現在のブラウザ上の学習対象合計は3,991語です。

シラバス補助データは用語名と分類をもとに、アプリ用の短い説明・着眼点・関連語を独自に付与しています。過去問やPDF本文の説明文は転載していません。

各用語は次の項目を持ちます。

- `id`
- `用語`
- `系`
- `大分類`
- `中分類`
- `小分類`
- `英語`
- `基本解説`
- `試験での着眼点`
- `関連語`
- `検索語`
- `出典`（シラバス補助データのみ）

`系` は `テクノロジ系`、`マネジメント系`、`ストラテジ系` の3種類です。

### 画面遷移

下部ナビゲーションの `data-nav` により、次のビューを切り替えます。

- `home`: 今日の学習、進捗、分野別状況、優先復習
- `map`: 知識マップ。用語検索、分野・習熟状態・記述状態の絞り込み、カテゴリ開閉、用語詳細、関連問題、記述欄、画面共通の暗記モードを扱う
- `quiz`: 4択問題演習
- `review`: 問題による復習とChatGPTによる記述復習。復習期限、誤答、苦手、分野別復習、記述確認、修正メモ反映を扱う
- `progress`: 学習準備度、学習状態割合、記述/テスト進捗、14日間の学習量、苦手分野、分野別成績、誤答ランキング
- `settings`: 目標、試験予定日、テーマ、バックアップ、復元、データ削除

下部ナビは `ホーム / マップ / 問題 / 復習 / 分析 / 設定` の6項目です。旧 `study` と `terms` のURL指定は互換性のため `map` へリダイレクトします。PWAショートカットでは `./?view=quiz` と `./?view=map` を使い、起動時に指定ビューへ移動します。

### 出題と復習ロジック

- 出題モードは `recommended`、`random`、`weak`、`due`、`unlearned` を持ちます。
- 問題形式は `description`（説明から用語を選ぶ）、`term`（用語から説明を選ぶ）、`mixed` です。
- 不正解選択肢は、同じ中分類を優先し、不足する場合は大分類、系の順で候補を広げます。
- 回答後は `attempts` に履歴を追加し、用語ごとの `correct`、`wrong`、`streak`、`mastery` を更新します。
- 演習中は `quizDraft` に現在位置と回答済み結果を保存します。「演習設定に戻る」または「中断して保存」で設定画面へ戻れます。再開時は回答済み問題を再採点しないため、累計成績は二重加算されません。
- 復習日は既存互換のため `due` に保存し、同じ日付を `nextReview` にも同期します。誤答や低評価では翌日復習、理解できた場合は簡易的な間隔反復で次回日を延ばします。
- 復習優先度は理解度、誤答回数、最終学習日、連続正解数、復習期限の超過日数から計算します。
- `due` モードとおすすめ演習は、復習期限の用語、忘れかけている用語、未学習語を区別して扱います。
- 科目A対策は用語4択とは別の問題データを使い、ランダム、苦手優先、未学習優先、分野別、模試形式の入口を持ちます。サンプル問題はオリジナル問題のみです。
- 学習準備度は学習済み語数の割合と累計正答率から算出する参考値です。合格確率ではありません。
- 分析画面では、未学習・学習中・習得済みの割合、最近14日間の解答数、誤答ランキング、苦手分野、次のおすすめ行動を表示します。

### 知識マップ

知識マップは、画面上ではツリー形式で表示し、内部データは有向グラフとして扱います。`assets/knowledge-map-data.js` の手作り初期データ50語は、短い説明、詳しい説明、具体例、重要度、難易度、前提関係を持つ詳細ノードとして扱います。これに加えて、起動時に既存の学習対象3,991語をすべて知識マップへ自動取り込みし、`系 > 大分類 > 中分類 > 小分類` の122カテゴリへ配置します。

全用語取り込みは保存データではなく実行時生成です。既存の `localStorage` には未操作の用語を追加保存しないため、過去の学習履歴やバックアップ形式は維持されます。既存用語の `関連語` から `related` 関係を自動生成し、手作り初期データに登録済みの `prerequisite`、`comparison`、`included` 関係はそのまま優先します。

- `Subject`: 分野。例: テクノロジ系、マネジメント系、ストラテジ系
- `Category`: 階層カテゴリ。例: コンピュータシステム > コンピュータ構成要素 > CPU
- `Term`: 知識マップ用語。名前、短い説明、詳しい説明、具体例、重要度、難易度を持つ
- `TermRelation`: 用語間の関係。`prerequisite`, `related`, `comparison`, `derived`, `included` を扱う
- `QuestionTerm`: 問題と用語の関連付け。`primary`, `related`, `prerequisite` と重みを持つ

既存の学習履歴は `fe-learning-os-v2` のまま維持します。知識マップの `UserTermProgress` 相当の値は、既存の `terms` と `attempts` から互換的に算出します。未操作の用語をlocalStorageへ追加保存しないため、既存データやバックアップ形式を壊しません。

科目Aや知識マップ関連問題の回答は `QuestionTerm` の `role` と `weight` に従って、主対象、関連語、前提語へ重み付きで反映します。通常の解答履歴数を増やしすぎないよう、関連語・前提語への反映は `knowledgeCorrect` / `knowledgeWrong` に保存します。

状態判定は以下を基本にしています。

- `locked`: 必須の前提用語が学習条件を満たしていない
- `unlearned`: 問題未回答かつ用語学習未完了
- `learning`: 学習中
- `review`: 復習期限に達している
- `weak`: 直近誤答または習熟度が低い
- `mastered`: 習熟度80以上、回答3回以上、直近2回以上連続正解

スマートフォンでも色だけに依存しないよう、各ノードには `LOCK`, `未`, `学`, `復`, `苦`, `済` の状態マーカーを表示します。

表示はスマートフォン優先です。カテゴリはボタンで開閉でき、初期表示では大分類と主要カテゴリだけを開いて描画量を抑えます。検索や状態絞り込み時は該当カテゴリを自動で開き、カテゴリ内の用語は段階表示します。全体図パネルでは分野別・大分類別の用語数、平均習熟度、未学習、苦手、習得済みの数を俯瞰できます。

各用語の詳細には「自分の言葉でまとめる」欄があります。用語名を含む問いを表示し、1〜3文を目安に自分の説明を入力できます。入力内容は自動保存され、記述欄の見出し横にある小さい「↑ 前へ」「↓ 次へ」ボタンで表示中の用語を移動できます。デスクトップでは `Ctrl + ArrowUp` / `Ctrl + ArrowDown` でも移動できます。

用語カードの「関連用語」は画面遷移せず、現在のカード下にアコーディオンとして展開します。各関連語には学習状態、正答率、重要度、難易度、マップ登録状況を表示します。登録済みの関連語を押すと、親カテゴリを開いて該当ノードへスクロールし、選択状態として強調します。ブラウザの戻る操作では、元の用語カード、検索条件、関連用語の展開状態、スクロール位置へ戻ります。

知識マップには暗記モードがあります。ONにすると、問いは表示したまま全用語の「自分の記述」だけをカバーで隠します。記述内容やtextareaの高さは維持され、暗記モードOFF、長押し表示、すべて表示、またはセンサによる一時表示で確認できます。

- `暗記モード`: 自分の記述を隠す/通常表示に戻す
- `センサ操作`: iPhone Safariなどで許可後、端末方向センサを使って現在用語だけ一時表示する
- `長押しで答えを見る`: 押している間だけ現在用語の記述を表示する
- `すべて表示`: 暗記モードを維持したまま全記述を一時表示する
- `センサ再調整`: その時点の自然な持ち方を基準姿勢にする

センサ判定は、暗記モード開始時または再調整時の姿勢を基準にした相対角度で行います。初期値では25度以上の傾きを約0.5秒維持すると現在用語だけ表示し、10度以内へ戻ると再び隠します。小さな揺れで点滅しにくいよう、移動平均とヒステリシスを使っています。センサが使えない端末や許可を拒否した場合でも、ボタン操作だけで同じ学習ができます。

答えを見た後は、各用語で「覚えていた」「あいまい」「覚えていなかった」を押して暗記自己評価を保存できます。この評価は正式なテスト正答率には加算しません。「あいまい」「覚えていなかった」は復習候補へ寄せるため、既存の正答数・誤答数を増やさずに復習期限と弱点理由だけを更新します。

進捗は混ぜずに、次の2系統で表示します。

- 記述進捗: 未記入、下書き、記入済み、確認待ち、確認済み、要修正、理解不足、再確認待ち
- テスト進捗: 未出題、学習中、苦手、習得済み

記述済み判定は、空白を除いて10文字以上の入力を基準にします。分析画面では記述進捗率、テスト習熟率、両方完了、記述だけ、テストだけ、両方未完了を分けて表示します。

### GitHub PagesとPWA

GitHub Pagesの `https://12rxxll.github.io/Fe/` 配下で動かすため、HTML、manifest、service worker、アイコン、CSS、JSは相対パスで参照します。`/` 始まりの絶対パスは使いません。

Service Workerは登録scopeを基準にキャッシュURLを組み立てます。主要ファイル、用語データ、シラバス補助データ、科目Aデータ、知識マップデータ、manifest、PWAアイコンをキャッシュし、オフライン時の画面遷移は `index.html` にフォールバックします。

ナビゲーションはネットワーク優先、静的資産はキャッシュを返しつつ裏で更新する方針です。新しいService Workerが待機状態になった場合は、画面下部に更新ボタンを表示して再読み込みを促します。

### 暗記モードの保存データとプライバシー

暗記モードでは外部API、外部CDN、アクセス解析、カメラ、マイク、位置情報を使いません。端末方向センサの値は画面上の表示判定だけに使い、localStorageやバックアップには保存しません。

localStorageに保存するもの:

- 暗記モードの初期ON/OFF
- センサ操作の初期ON/OFF
- 表示開始しきい値、非表示しきい値、維持時間
- 手動表示方式
- センサパネル表示設定
- 暗記モード専用の自己評価

localStorageに保存しないもの:

- `beta` / `gamma`
- 基準姿勢
- センサ履歴
- 端末の姿勢履歴

## 手動テスト手順

フェーズごとに、次を確認してから次の変更へ進みます。

1. ローカルHTTPサーバで `/Fe/` 配下として表示する。
2. 320px、375px、390px、430px、PC幅で横スクロールや文字の重なりがないことを確認する。
3. ライト・ダーク両方のテーマで、ホーム、マップ、問題、復習、分析、設定を確認する。
4. コンソールエラーがないことを確認する。
5. `manifest.webmanifest`、`assets/styles.css`、`assets/app.js`、`assets/terms-data.js`、`assets/syllabus-terms.js`、`assets/subject-a-data.js`、`sw.js`、各アイコンがHTTP 200で取得できることを確認する。
6. マップ検索で既知の用語が見つかり、用語カードの問い、記述欄、前後移動、説明・関連情報、復習・問題、詳細進捗の開閉が動くことを確認する。
7. 用語4択と科目A演習を開始し、1問回答してフィードバック、解説、結果画面が表示されることを確認する。

## AI機能について

完全無料を維持するため、OpenAI APIは組み込んでいません。ChatGPT連携は、プロンプトを生成してクリップボードへコピーし、可能ならChatGPTを開く方式です。

ChatGPT機能は2系統に分けています。

- 用語単位: マップの用語カードで「説明・関連情報」を開くと、小さな「ChatGPTに説明を聞く」ボタンがあります。その用語名、登録済み説明、前提用語、関連用語、重要度、難易度だけを含む説明質問プロンプトを作ります。自分の記述、学習履歴、個人情報は含めません。
- 複数用語まとめ: 復習画面の「ChatGPTで記述を復習」で、複数用語の自分の記述をまとめて添削用プロンプトにします。送信履歴、確認結果、修正メモ、重複送信防止はここで管理します。

復習画面では、記述済みの内容をまとめてChatGPTへ確認依頼するプロンプトを生成できます。

- 未送信の記述だけをまとめる
- 前回送信後に更新された記述をまとめる
- 分野単位でまとめる
- 任意に選択した用語だけをまとめる
- マップ選択中の用語だけをまとめる
- 送信前に対象用語数、範囲、分野、推定文字数を確認する
- 20語または約8,000文字を目安にバッチ分割する
- コピーまたはChatGPTを開いたタイミングで送信履歴を保存する
- 前回送信時と同じ内容は既定で除外する
- 前回送信後に編集した内容は再送対象にする
- ChatGPTの回答を見た後、復習画面で用語ごとに「正しい」「一部修正が必要」「理解不足」「未確認」を手動で記録できる
- 修正メモを保存でき、「要修正」だけで絞り込める
- 修正メモは「記述へ反映」から、追記、置き換え、編集統合のいずれかでマップの記述へ反映できる
- 反映後は「再確認待ち」として扱い、前回送信内容とは異なるため次回の送信候補に戻る
- 反映前の記述は `noteRevisionHistory` に残り、「元に戻す」で直前の反映を取り消せる

補助AI導線では、次のプロンプトを生成できます。

- この用語を初心者向けに説明
- 間違えた理由を分析
- 関連問題を3問作成
- 今日の弱点を整理

プロンプトに含める学習情報は、用語名、分野、誤答回数など最小限に抑えます。
